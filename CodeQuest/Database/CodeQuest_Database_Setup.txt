CODEQUEST DATABASE SETUP
========================

AUTOMATIC LOCAL SETUP (DEFAULT)
-------------------------------
1. Install Visual Studio's "Data storage and processing" workload, or install
   SQL Server Express LocalDB separately.
2. Open CodeQuest.slnx and run the web application.
3. On the first database request, CodeQuest automatically creates CodeQuestDB,
   applies CodeQuest_Database.sql and Progress_Extension.sql, and inserts the
   demo content from Seed_Demo_Content.sql.

No SQL query needs to be copied into Visual Studio. The scripts are
idempotent, so restarting or pulling newer code does not delete existing data
or duplicate the demo records.

The checked-in Web.config enables this behavior with:

<appSettings>
  <add key="CodeQuestAutoInitializeDatabase" value="true" />
  <add key="CodeQuestSeedDemoContent" value="true" />
</appSettings>

The application still needs a SQL Server engine. Git can carry schema and seed
scripts, but it cannot install LocalDB on another user's computer.

CONFIGURATION
-------------
The default local connection is:

<connectionStrings>
  <add name="CodeQuestDb"
       connectionString="Data Source=(LocalDB)\MSSQLLocalDB;Initial Catalog=CodeQuestDB;Integrated Security=True;MultipleActiveResultSets=True"
       providerName="System.Data.SqlClient" />
</connectionStrings>

The initializer uses the server and database name from this connection string.
Set CodeQuestSeedDemoContent to false to create only the schema. Set
CodeQuestAutoInitializeDatabase to false when the database is managed outside
the application. The Release Web.config transform disables both settings by
default; production schema changes should be deployed deliberately with a
restricted database account.

MANUAL FALLBACK
---------------
If automatic initialization is disabled, execute these files in order using
SQL Server Object Explorer or SQL Server Management Studio:

1. Database/CodeQuest_Database.sql
2. Database/Progress_Extension.sql
3. Database/Seed_Demo_Content.sql (optional)

IMPORTANT SECURITY NOTES
------------------------
- Store a salted password hash in User.password, never the plain password.
- Store a hash of password-reset tokens in Token.token when possible.
- Payment transaction references should come from the payment provider.
- Do not commit API keys, OAuth client secrets or SMTP passwords to source
  control. Use local configuration or environment-specific deployment values.
